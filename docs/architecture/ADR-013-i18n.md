# ADR-013 — Locale and internationalization

## Status

Accepted for the browser-readiness foundation.

## Decision

Use the existing `@risexpto/i18n` package as the single locale type and translation catalog. Supported locales are `en` (default), `pt-BR` and `es`. The Web `LocaleProvider` synchronizes the locale between immediate client state, an `rx-locale` cookie for SSR and the persisted authenticated `UserProfile` preference through the profile API.

No browser-only locale decision is authoritative for authorization or financial calculations. New UI copy must be added to the catalog before being used in translated surfaces.

## Consequences

The browser-readiness slice now covers the landing, navigation, locale selector,
Settings persistence and authenticated workspace surfaces. Any new UI copy must
continue to be added to all three catalogs.

# ADR-013: Internationalization

## Decision

The Web and shared package use the supported locales `en`, `pt-BR`, and `es`, with English as the fallback. Preference resolution is profile/session first, then the `rx-locale` cookie, then local storage/browser language, and finally English. Changing locale updates the rendered client UI immediately and persists the cookie/local storage; authenticated Settings also persists the profile preference.

OIDC login receives a validated `ui_locales` value when the entry point has a selected locale. Technical identifiers such as symbols, provider names, API and currency codes remain unchanged.

## Status

The authenticated workspace catalog and live Keycloak/browser validation were
completed in phases 77 and 79. RiseXPTO keeps `pt-BR` internally; Keycloak 26.3
receives `pt` because that is the locale identifier supported by its built-in
Portuguese messages. The explicit current selection is authoritative, then the
persisted profile/session is synchronized with the `rx-locale` cookie; pathname
navigation never re-applies an older profile value.

The Keycloak theme keeps the provider-native locale mechanism (`ui_locales` and
the realm locale selector) and styles its compact control locally. Provider
values remain `en`, `pt` (for RiseXPTO `pt-BR`) and `es`.

Public locale changes are a separate persistence boundary: landing and public
auth surfaces update only the browser cookie, local storage and document
language. Authenticated workspace changes first confirm the sealed session,
then update AuthSession and `UserProfile` through their existing endpoints. An
anonymous browser must never call authenticated preference mutation endpoints.
